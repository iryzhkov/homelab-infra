# Metrics-only embedding review

Prepared source only: no externally shared dashboard, public URL, anonymous Viewer account or Home Assistant UI change has been created. The normal Home Assistant dashboard is the seventh authenticated observability dashboard; its default datasource is only `homelab-metrics`. Six existing dashboard UIDs and resources stay intact and receive its navigation link.

Three separate aggregate dashboard copies are available as `embed-overview.json`, `embed-agents.json`, and `embed-homeassistant.json`. They have fixed queries, no template variables, no annotations, no Loki datasource or log panel, no entity/host/room labels in returned series, and no navigation links to private dashboards. Their datasource is solely `homelab-metrics`. They are provisioned as ordinary authenticated dashboards through `observability_grafana_embedding_dashboard_files`; externally shared capability access remains disabled until explicitly requested with `observability_grafana_sharing_enabled`. Provisioning these ordinary dashboards does not create a public link.

## Preferred private authenticated iframe

The standalone draft `files/homeassistant-observability-draft.yaml` uses Home Assistant's standard Webpage card with HTTPS Grafana URLs in three tabs and kiosk presentation. It avoids modifying the generated HA home dashboard. After review, the owning HA repository can add `dashboards/observability.yaml` and one explicit `lovelace.dashboards.dashboard-observability` YAML entry (title Observability, icon mdi:chart-box-outline, sidebar true). The dashboard contains no device controls or log panels. HA configuration check and activation/reload must be coordinated separately.

Grafana must allow embedding (`GF_SECURITY_ALLOW_EMBEDDING=true`), retain secure cookies, and keep global anonymous authentication disabled. Coordinate this environment change with the logging/Influx migration owner; do not restart Grafana as part of dashboard API provisioning. Home Assistant and Grafana HTTPS URLs share the same site (`ryzhkov.dev`), but browser authentication still needs testing: first open Grafana directly and log in, then test iframe session reuse, fresh/incognito browsers, phone/tablet layout, and the existing Authentik redirect/CSP headers. An HA session is not a Grafana session; do not bypass the identity layer to make an iframe appear logged in. If login redirect cannot run inside the frame, open Grafana directly to establish its session.

## Optional external capability links: exposure review required

Grafana externally shared dashboards allow anyone holding the link to read their fixed dashboard queries without a Grafana login. This is distinct from globally enabling anonymous login or creating an anonymous Viewer account. The URL is an access capability: forwarded/copied links grant access until paused or revoked. Existing authenticated dashboards should never be shared directly because they expose entity names, host identities, detailed resource labels and navigation.

The prepared aggregate views still expose infrastructure capacity, scrape failures, backup age, worker resource use, and home temperature/humidity/device-power and availability trends. Even without names or logs, time series can reveal workload schedules and household activity. Worker scope uses a generic `agent-.*` hostname pattern rather than individual inventory identities. Treat dashboard metadata and query definitions as visible even though returned series labels are aggregated. They do not grant arbitrary datasource querying; externally shared dashboards run only stored queries. Templates/queries with variables are unsupported, hence the separate fixed-scope copies. If explicitly approved, create shares only for these three UIDs, disable annotations and time-range controls initially, verify unauthenticated access is confined to their metrics, and store actual capability URLs privately. No URL has been generated by this preparation.
