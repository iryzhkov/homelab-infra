# Metrics-only Home Assistant embedding

The user explicitly selected no-login aggregate capability links on 2026-10-13. Three externally shared copies are live: overview, agent-host resources and Home Assistant. Existing detailed dashboards remain authenticated; global Grafana anonymous authentication is disabled. Capability tokens and URLs are encrypted in `secrets/observability-grafana-shares.sops.yaml` and stored only in private HA UI state after reconciliation. Do not print them, paste them into Git, or link a detailed dashboard publicly.

Copies contain fixed aggregate `homelab-metrics` queries only: no Loki/logs, entity or host labels in returned series, template variables, annotations, or private navigation links. Source definitions and titles are visible to link holders. Aggregated workload, capacity, backup age, home temperature/humidity/power/availability trends can still reveal schedules and household activity. A copied link grants access until its share is paused/revoked. These shares execute stored queries, not arbitrary datasource exploration. Physical CPU/memory aggregate only declared physical hosts to avoid counting guests twice.

Normal API provisioning creates ordinary authenticated copies. Sharing requires explicit `observability_grafana_sharing_enabled=true`; only the three aggregate UIDs are allowed. Existing mismatched capabilities fail safely rather than being replaced. Source guards reject log sources, variables, annotations, private links and sensitive entity selections; actual query results must have no metric labels before sharing reconciliation. The public API preserves disabled annotations and time-selection controls. Alert resources are untouched.

Grafana framing was enabled during the coordinated logging migration after accepted Influx separation. Dashboard provisioning never restarts Grafana. The HTTPS ingress preserves certificate verification and omits a conflicting X-Frame-Options header.

Run `ansible-playbook playbooks/observability-homeassistant-embedding.yml --check` on the operator controller, then the same command without `--check` to reconcile the owned HA storage dashboard `/homelab-observability`. This reads existing Home Assistant operator credentials from the keyring service `homeassistant` in memory and reads the SOPS capability file; neither is printed. Requires Node with WebSocket, SOPS/age credentials, keyring access and trusted HTTPS connectivity. Three tabs use official Webpage cards in kiosk presentation. It preserves all other dashboards, refuses overwriting foreign ownership/YAML dashboards, and uses HA's WebSocket UI APIs without a Core restart. Its second application returned zero changes.

Unauthenticated browser acceptance verified all three Grafana copies: 18 successful panel-query responses, zero failures/JS errors, no host/entity labels. HA browser acceptance verified the live embedded overview (six public panel queries, no failures/errors) after framing activation. Other tabs/mobile checks follow the final dashboard deployment window. Missing data is unavailable, not fabricated.

The prior `files/homeassistant-observability-draft.yaml` is an unactivated authenticated-iframe alternative; the live implementation is the storage helper above. Detailed HA view remains private; retained historical HA queries continue using Influx.
