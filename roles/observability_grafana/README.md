# Grafana observability provisioning

Run `ansible-playbook playbooks/observability-grafana.yml --check` to inspect drift through read-only GET requests, then run without `--check` to reconcile. No alerts or notification resources are managed.

The role owns datasource `homelab-metrics`, folder `homelab-observability`, nine private `homelab-observe-*` dashboards (overview, hosts, disks, capacity, containers, logs, agents, unifi, homeassistant), three aggregate embedding copies, and three explicitly allowlisted existing dashboard UIDs. Existing Home Assistant history, Homelab Overview and Security & Auth dashboards retain their identity and folder. The original Loki and Influx sources are retained; detailed HA history continues using retained Influx. Other dashboards are preserved.

Adding a host requires inventory membership, collector convergence and explicit metadata classification, then the normal Ansible monitoring playbooks. `playbooks/observability-host-metadata.yml` emits declared physical/VM/LXC identity and capabilities; existing collector setup emits real node metrics with stable host/job/instance labels. Host Focus and CPU/GPU selectors query `node_monitoring_host_info`, and Disk Health queries actual `smartctl_device` labels. No JSON host list or dashboard-per-host edit is required. Refresh the dashboard after ingestion. New capabilities must be declared and an actual supported exporter installed; declaring SMART does not invent readings. There is no unsolicited automatic deployment timer.

Host CPU/RAM gauges prefer authoritative Proxmox accounting for mapped `guest_id` identities, falling back to native OS metrics otherwise. Per-thread bars are reported logical CPU IDs (SMT/vCPU), not physical cores or allocated LXC capacity. Overall CPU counts only explicitly physical hosts and weights each reported logical CPU equally; guest demand stays separate. Hardware temperature/SMART joins explicit capability metadata on host, excluding inherited LXC sensors. Physical drive/GPU inventory tables include declared unsupported devices explicitly. Drive selections use stable host/serial identity, joined to actual SMART devices; duplicate-model labels fall back to full device identity. Optional detailed error-history support remains separate from supported aggregate error counters. Passthrough GPU ownership carries the physical PCI identity so each GPU is counted once. Native desktop readings require successful collection and an age below 180 seconds; Intel engine readings likewise require fresh timestamps. Inventory-only GPUs have no fabricated utilization/temperature/status values. GPU busy duty cycles do not express FLOPs; absent GPU temperature or unmonitored discrete GPU performance remains unavailable.

Disk Health reports SMART status, temperature, vendor operating headroom, NVMe estimated endurance consumed, separate SATA vendor lifetime attribute, actual error counters and power-on time. SMART PASS cannot guarantee health or predict a failure date. Manufacturer-specific and unsupported fields remain unavailable, never a synthetic healthy zero.

Credentials are loaded from encrypted SOPS on the controller and marked secret in the module. API requests use Grafana's managed-host loopback listener; the metrics datasource uses a stable private Swarm service name. Move Grafana through the portable logging stack, then converge this role on its new inventory host. IDs/versions are retained when API updates reconcile committed JSON; server-generated additional defaults are tolerated. An occupied metrics UID with a non-Prometheus type fails safely.

The existing Loki UID is discovered by type; exactly one is required. Labels expect stable host/job/instance identities. Optional quota/token metrics remain unreported rather than inferred from host usage. See [AUDIT.md](AUDIT.md) for retained legacy repairs and [EMBEDDING.md](EMBEDDING.md) for restricted capability sharing.

The metadata role's synthetic new-host fixture verifies automatic inventory rendering without editing dashboard JSON; it is not a claim that a real new host was added. Live query and browser acceptance must follow collector readiness. Readiness checks use datasource health and proxied Prometheus up; successful empty results are accepted during initial collector installation. Check mode performs GETs only and guards against POST/PUT/DELETE.
