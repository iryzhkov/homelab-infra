# Existing dashboard adoption and query repair

The three pre-existing dashboard UIDs are explicitly adopted by Ansible without moving their folders or deleting any dashboards. Saved originals remain private in `/tmp/grafana-legacy-{ha,overview,security}.json`; dashboard histories remain available in Grafana. The module refuses any other legacy UID and permits external sharing only for the three separate aggregate copies.

Before repair, the 21 legacy queries included three reproducible HTTP 400 errors: both Home Assistant presence/sleep Flux timelines combined string and numeric `_value` schemas after removing their grouping fields; the Traefik error regex used invalid escaped syntax. Three current HA statistics were empty because 2–10-minute windows on event-driven Influx writes do not represent current state.

Repairs preserve historical Influx charts and its datasource UID `bfn7e4xhxpce8d`, normalize timeline values to strings, and use native VictoriaMetrics measurements for current light states, thermostat temperature and thermostat mode. Humidity uses percent units. Native current-temperature Celsius is converted to Fahrenheit for consistency with the existing historical dashboard.

Legacy Loki charts now normalize old `container_name` and new `container` labels without dropping retained history; PVE journal selectors accept actual `journal` and `systemd-journal` jobs with confirmed Proxmox inventory host labels. Traefik status matching accepts common JSON status fields and text access-log formats. Authentication/password-manager inputs remain deliberately excluded; their panels explicitly describe retained historical coverage instead of reenabling sensitive collection.

Initial repaired-query acceptance: 21/21 valid queries; all 10 HA queries return data, all 6 legacy overview queries return data, and 2 security queries return events. The three empty security windows are expected: Authentik/Vaultwarden excluded and no matching Traefik errors. No alert/notification resource changes are included. The retained Influx datasource remained healthy after the standalone legacy-stack cutover; Grafana's query API accepted all historical HA panels. A later full screenshot audit found empty event-driven windows broke timeline rendering despite HTTP 200; the final repair seeds each timeline with its actual last observed pre-window state and renders state labels/colors.

Baseline deployment acceptance on 2026-10-13 (source d0012ee): all 152 stored queries across 15 dashboards returned HTTP 200 without backend errors. Expected empty families were the pending native stewardship producer, optional container filesystem, deliberately excluded Authentik/Vaultwarden inputs, and a window without Traefik errors. A temporarily empty WAN-role query was checked separately and confirmed actual ACTIVE/BACKUP values. Normal Grafana Ansible reruns reconciled zero resources after deployment.

Private desktop/mobile browser full-scroll acceptance covered Disk Health, CPU/GPU, Host Focus on a physical PVE host and CT105, a SATA-only selection, and the retained HA dashboard; no query or JavaScript errors were found. CT105 inherited sensors remain excluded; its host CPU/RAM gauges use authoritative PVE guest accounting. The original per-thread renderer sorted lexically despite query sorting; the repaired renderer reduces frames and sorts padded numeric thread IDs. Initial physical CPU pool had 38 reported logical CPUs (gaming-pc 12, laptop 8, proxmox-a 12, proxmox-b 6), counted once. Initial SMART readings covered four PVE drives, and two Intel passthrough devices supplied distinct engine duty cycles; expanded physical inventory is validated separately after producer rollout.

Three aggregate copies and all six Home Assistant iframe tab/layout combinations (desktop/mobile) were verified without private labels, log panels or capability URL disclosure. HA config and embedding Ansible check/normal runs each returned zero changes and no extra Core restart. Seven owning-source HA reconciliation tests cover read-only check, maintenance refusal, native-check rollback and change-only explicit restart.

Actual SMART inventory/health now covers all seven SSDs (PVE four, desktop two, laptop one), missing declared devices zero; all five physical GPU identities remain visible, including Apple inventory-only support.
