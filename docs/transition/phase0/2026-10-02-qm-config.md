## Hot-plug feasibility

All four VMs keep the default `hotplug: network,disk,usb`. Proxmox attaches
virtio-scsi controllers and NICs to its own PCI bridges (pci.1-pci.3) on both
i440fx and q35, so hot-plug goes through SHPC/ACPI on those bridges, not through
PCIe root ports. On q35 the `ich9-pcie-port-*` ports are used only for
`pcie=1` passthrough.

- Free slots: pci.3 holds only the per-disk SCSI controllers at addr 0x1-0x2
  (32 slots per bridge), pci.1 and pci.2 are empty; NICs net2+ have reserved
  addresses on pci.0/pci.1. Slots are not a constraint.
- Guest drivers: `acpiphp` and `pciehp` are built into every guest kernel
  (`/sys/module/acpiphp` and `/sys/module/pciehp` exist; `CONFIG_HOTPLUG_PCI_ACPI=y`,
  `CONFIG_HOTPLUG_PCI_PCIE=y`, plus `CONFIG_HOTPLUG_PCI_SHPC=y` on the Debian 12
  guests, kernel 6.1.0-52-amd64; normandy runs 7.2.5-3-omarchy). `lsmod` shows
  nothing because they are not modules. 123 to 160 entries in `/sys/bus/pci/slots`.
- Disk hot-add as a new `scsiN` on virtio-scsi-single (a new controller on pci.3)
  should work on 102, 106 and 202, and on 101 too, since a new SCSI disk does not
  depend on the existing virtio-blk boot disk. Changing options of an existing
  disk (`discard`, `ssd`, `cache`) cannot be hot-applied; that is why 101 and
  106 have pending changes.
- NIC hot-add is supported by the configuration (hotplug includes `network`).
  It has not been exercised on any of these VMs.

## Proxmox firewall and ipfilter (item 8)

- `/etc/pve/firewall/` is empty on the cluster: no `cluster.fw`, no `106.fw`.
- `pve-firewall status`: `Status: disabled/running`.
- `pvesh get /nodes/hp-elite-mini-01/qemu/106/firewall/options` returns only a
  digest, so `enable` and `ipfilter` are at their defaults (off).
- `pvesh get /cluster/firewall/options` failed with `unknown schema type (not an
  object?)` / `Compilation failed in require at /usr/bin/pvesh line 6`, while
  `pvesh get /version` works. Not investigated further; worth a look before the
  firewall is relied on.

The `firewall=1` flag on 101, 102 and 106's NICs only inserts a firewall bridge;
with the datacenter firewall disabled no rules or IP filter apply. A VIP on VM
106's NIC is not blocked by Proxmox `ipfilter`.

## Recorded answer

All VMs are i440fx except 202 (q35), all keep default hotplug `network,disk,usb`,
free bridge slots exist and guests have ACPI/PCIe hot-plug built in, so SCSI disk
and NIC hot-add should work; VMs 101 and 106 carry pending disk changes
(discard=on, and cache=none on 101; ssd=1 on 106) that the next stop/start
applies; ipfilter is off (no firewall config at all).
