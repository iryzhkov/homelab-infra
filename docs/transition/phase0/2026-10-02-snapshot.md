## What the script captures

`scripts/snapshot.sh` is read-only on every host. Over SSH it collects:

- Docker hosts (homelab, public-api, normandy, blackpearl): Compose files, Dockerfiles, `*.sh`, `traefik.y*ml`, systemd units under the stack directories (`~/app`, `~/apps`, `~/cv-site`, depth 3, files under 1 MB); facts files `containers.txt`, `compose-projects.txt`, `volumes.txt`, `networks.txt`, `crontab.txt`, `systemd-enabled.txt`, `systemd-user-enabled.txt`, `os.txt`, `packages.txt`, `mounts.txt`; and Compose files of leftover Portainer stacks.
- Proxmox nodes: `qm list` and `pct list`, `/etc/pve/storage.cfg`, `pveversion -v`, `/etc/pve/jobs.cfg`, `/etc/network/interfaces`, and every guest config concatenated into `guests/all.conf`.
- Whole directories: public-api `~/apps/traefik/file_provider` and homelab `~/app/traefik`, skipping `.env`, `*.env`, `acme.json`, `*.key`, `*.pem`.

Secrets are not collected (that is `scripts/collect-secrets.sh`, not run here).

The script overwrites files in place and never deletes, so files captured by earlier runs (the previous run was 2026-09-06) that no longer exist on a host are still present in `snapshot/`. The facts files are all rewritten on every run and are current.

## Implications for later phases

Because `snapshot/` is never pruned, a later after-picture should be taken into a clean directory (or `snapshot/` moved aside first) so that files removed during the transition show up as removed rather than lingering from this run.
