# Phase 0 check: ZFS ARC limits

Measured 2026-10-02 12:57 PDT on proxmox-a (hp-elite-mini-01) and proxmox-b
(hp-workstation-01). Kernel 7.0.14-14-pve, `zfs-2.4.4-pve1` /
`zfs-kmod-2.4.4-pve1` on both.

## Commands and output

`lsmod | grep -E '^(zfs|spl) '`: `zfs` and `spl` loaded on both.

`cat /sys/module/zfs/parameters/zfs_arc_max`: `0` on both (`zfs_arc_min` also 0).

`grep -r arc /etc/modprobe.d/`: no output on either host. The initramfs
(`lsinitramfs`) carries no `zfs.conf` either. `/proc/cmdline` has no `zfs.`
parameter on either host.

`/proc/spl/kstat/zfs/arcstats`:

```
proxmox-a  c_max 62951 MiB  c_min 1999 MiB  size 0 MiB
proxmox-b  c_max 30848 MiB  c_min  996 MiB  size 0 MiB
```

`free -m`:

```
proxmox-a  total 63974  used 48170  free 6792  available 15804  swap used 3417 of 8191
proxmox-b  total 31871  used 27056  free  599  available  4815  swap used  614 of 7715
```

`zpool list`: `no pools available` on both.

## Finding

`zfs_arc_max=0` does not mean 50 % of RAM on this ZFS version. Since OpenZFS
2.3 the Linux default is all memory minus 1 GiB, and arcstats confirms it:
`c_max` is 62951 MiB of 63974 MiB on proxmox-a and 30848 MiB of 31871 MiB on
proxmox-b, exactly total minus 1023 MiB. The Proxmox installer writes a 10 %
limit only for fresh ZFS installs; these hosts were installed on LVM, so nothing
limits the ARC. It is harmless today only because no pool exists (ARC size 0).

## Recorded answer

No, `zfs_arc_max` is not set anywhere on either host (0 everywhere), and on
zfs 2.4.4 the effective default is RAM minus 1 GiB (62951 / 30848 MiB), not 50 %.

## Implications for later phases

- Phase 2 must set the ARC limit before creating `tank`, both live
  (`/sys/module/zfs/parameters/zfs_arc_max`) and persistently
  (`/etc/modprobe.d/zfs.conf` plus `update-initramfs -u`), through the base role
  rather than by hand. proxmox-b has only 4.8 GB available today with 24 GiB
  given to normandy, so its limit must be small (a few GiB); proxmox-a has about
  15.8 GB available and 3.4 GB of swap already in use.
