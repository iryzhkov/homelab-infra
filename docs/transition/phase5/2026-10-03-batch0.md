Date: 2026-10-02, 20:40 to 20:55 PDT (2026-10-03 UTC). Executor E21.

## Verdict

The generator, the Gatus template, `site.yml` and the address filters now know about Swarm stacks. With no `swarm_stacks_*` entry, `site.yml --check`, `traefik.yml --check --diff` and `swarm.yml --check` report no change that comes from this batch. With a fake Swarm stack list passed as extra variables, the rendered differences are exactly the intended ones. The two Traefik templates batch 0 edits are also edited by phase 4; both merge without conflict.

## Files changed

- `filter_plugins/stacks.py`: new filters `swarm_stacks` (the union of every `swarm_stacks_*` list, read from the first worker's variables so it works on hosts outside group `swarm`, such as the edge proxy), `swarm_stack_names`, `stack_hosts`, `stack_host_ips`. `stack_host` and `stack_host_ip` return the bootstrap manager (`swarm_bootstrap_manager`, homelab) for a Swarm stack; a Swarm entry wins over a host_vars entry of the same name.
- `playbooks/site.yml` (step 1): the deploy loop rejects every stack named in a Swarm entry, with or without `only`. A targeted run naming a Swarm stack now removes its entry from the drift manifest (the manifest update ran only when something was deployed, and appended an undefined list otherwise).
- `roles/traefik/templates/generated.yml.j2` (step 2): a new block after the host_vars loop drops the routes of host_vars stacks that have a Swarm entry, and appends each Swarm route with one server per host of `swarm_workers`, keeping the route's health check; a route with an explicit `url` keeps it. A service's `servers:` is now a loop over `route.urls`, defaulting to the single `route.url`. Authentik's forward-auth address is the first worker's (homelab) once Authentik has a Swarm entry, homelab's Compose address before.
- `roles/traefik/templates/whisper.yml.j2`: the CPU fallback lists `stack_host_ips(groups, 'whisper')`, one server now, both workers once whisper is a Swarm stack.
- `stacks/gatus/templates/config.yaml.j2` (step 4): internal probes are gathered first, one per route for Compose stacks and one per route per worker for Swarm stacks, then rendered by the unchanged endpoint block; the public-from-LAN loop reads the same route list. Order of existing endpoints is unchanged, so the rendered file is identical while no Swarm stack exists.
- `docs/traefik-routing.md`: a "Swarm stacks" section.
- `roles/drift_check/**`: no change needed. Swarm stacks are not Compose projects (`docker compose ls` does not list them), and a full `site.yml` run writes a manifest without them.

Step 3 (`stack_host_ip`) is in the filter file above. Deviation from the plan's wording: servers are the hosts of `swarm_workers`, not of `swarm`. OCI is a drained manager whose `DOCKER-USER` drops traffic to `docker_gwbridge`, so its routing mesh answers nothing by design.

## Implications for later phases

- Every stack batch: add the stack's Swarm entry in the same change as its cutover and run `playbooks/traefik.yml` and `playbooks/site.yml -l homelab,normandy -e only=gatus` right after it. From the moment the entry exists, `site.yml` stops converging the Compose project, the route lists both workers and Gatus probes both, even if the cutover has not run yet.
- Until UniFi's `traefik-normandy-ports` holds a stack's port, Traefik marks the normandy server down and serves through homelab alone. Gatus is not affected: its probes run from homelab and normandy over VLAN 70, which the ingress filter does not drop (it drops only sources on `ens18` and `nebula1`). Batch S1 should confirm that both Gatus probes of excalidraw pass.
- Consumers that take one address (`stack_host_ip`, the forward-auth middleware, literal addresses in HA and the *arr apps) follow homelab, the bootstrap manager, and stop during a homelab drain.
