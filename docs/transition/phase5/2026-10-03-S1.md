Deviation from the plan's "pinned by tag as today": every image is pinned to the digest the
Compose container ran at conversion (`tag@sha256:...`). Reason: Swarm resolves a tag to the
registry's current digest at deploy, and librespeed's `latest` has moved since its container
started (running `431062ce...`, registry `069eb209...`), so a tag-only stack would have
upgraded during the move. Consequence: Swarm stacks are not covered by `docker-update` (it
reads Compose labels), so an image update is an edit of the digest. Open question for the
lead, below.

## Activation and cutover plan (stage 2)

The entry of one stack moves from `pending_swarm_stacks_s1` to a new list
`swarm_stacks_s1` in the same change as its cutover, then, in order:

1. `ansible-playbook playbooks/swarm.yml --tags stacks -e only=<name> -e swarm_cutover=<name>`
   (removes the Compose project, keeps nothing that matters: these have no volumes).
2. `ansible-playbook playbooks/traefik.yml`, then `ansible-playbook playbooks/site.yml -l
   homelab,normandy -e only=gatus`.
3. Verify: `docker service ps <stack>_<svc>` running; `curl -s -o /dev/null -w '%{http_code}'
   http://192.168.70.223:<port>/` and `http://192.168.70.234:<port>/` from homelab and from
   public-api; the public URL; the two Gatus probes green; Traefik's dashboard shows both
   servers up.
4. Record the interruption: from the `compose down` to the first 200 on the published port.

Order: excalidraw, librespeed, kiwix, flaresolverr. When the fourth has moved,
`pending_swarm_stacks_s1` is deleted.

## Open questions for the lead

- `roles/swarm/tasks/stack.yml` cannot check-run a stack before its first deploy (check 8),
  and it runs `prepare_tasks` after the render and before the "Refuse a cutover nobody asked
  for" assertion, so a run without `swarm_cutover` executes the preparation and then fails.
  Harmless for S1 (no preparation); S2 and S3 preparations only copy files.
- Image updates for Swarm stacks: `docker-update` does not see them. Digest pins make that
  explicit; a Swarm-aware update path is a later item.
