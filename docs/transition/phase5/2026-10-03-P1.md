## Fix after review, 2026-10-03: the pinned node comes from the label

The phase 5 Ansible review found that `stacks/miniflux/swarm-prepare.yml` took the node from the inventory's `swarm_stack.pin` instead of the `pin.miniflux` label, unlike the other prepare files (`stacks/actual/swarm-prepare.yml`). After a `swarm-move.yml` move, a stacks converge would have recreated an empty `/srv/swarm/miniflux` on the old node, and the `PG_VERSION` assert would have aborted the play there.

Fix: the file reads the label first (`docker node ls --filter node.label=pin.miniflux=true`, then the node's `host` label), as `actual` does, and falls back to the inventory's pin only while no node carries the label. The dump directory follows the same node. The "Compose project on the pinned node" assert and the state-directory creation now run only in a cutover. A check-mode-only variable, `swarm_prep_pin_override`, simulates the label on another node; outside check mode it is refused.

Proof, check mode only, no host change, during E28's move rehearsal (label read live: `pin.miniflux` on homelab):

- `ansible-playbook playbooks/swarm.yml --tags stacks -e only=miniflux --check --diff`: rc 0, `ok=35 changed=0`; "miniflux state: /srv/swarm/miniflux on homelab"; `Look for the copied database` ran on homelab; `Create the state directory` skipped.
- The same with `-e swarm_prep_pin_override=normandy`: rc 0, `ok=36 changed=0`; "miniflux state: /srv/swarm/miniflux on normandy"; `Look for the copied database` ran as `homelab -> normandy(192.168.70.234)`; `Create the state directory` skipped, so nothing would be created on homelab.
