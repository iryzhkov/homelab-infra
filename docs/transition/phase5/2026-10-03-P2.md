## The incident, and what this plan takes from it

`2026-10-02-incident-authentik.md`: `docker swarm leave --force` dropped the embedded DNS records of running Compose containers; Authentik's server and worker could not resolve `postgresql` and `redis` for 34 minutes (20:34 to 21:08), and the watchdog restarted the wrong containers for 30 of them. Taken into this plan:

- Nothing here leaves, re-inits or rebuilds the Swarm. The cutover only stops one Compose project and deploys one stack.
- Verification checks name resolution between the services from inside the tasks (`getent hosts postgresql redis` in server and worker), not only that the tasks run.
- The watchdog is retired, not repointed (below): Swarm's own health checks replace a failed task, and restarting server and worker was the wrong action in the incident.
- The interruption is short and bounded: the dump and its restore proof run while Compose still serves, so the outage is only stop, a local copy of about 120 MB, and start.
- Every step that changes data is reversible: the named volumes and directories Compose used are read, never written.

## Open questions

- homelab containers that use the Loki log driver (all were created with `loki-url http://localhost:3100/...`, not daemon.json's `192.168.70.223`) log push timeouts, and stopping such a container can hang for many minutes (`gatus`, `logging_grafana` did not answer `docker inspect`). Owner: F5/logging or the lead. Authentik uses the `local` driver and is not affected.

- `~/app/pg_backup.sh` (homelab crontab, Mon and Thu 01:30, not in the repository) dumps `authentik-postgresql-1` by name and stops working at the cutover (first missed run Monday 2026-10-05). `roles/backup/files/homelab-restore-verify` restores the newest `authentik_*` from `b2:igor-offsite-backup/apps/homelab/backups/postgres` as SQL and fails when it is older than five days, so from about 2026-10-06 the nightly verify fails. Both belong to the backup role (batch B or the lead): retire the cron line and point the verify at the hourly `-Fc` dumps under `b2:igor-offsite-backup/apps/homelab/swarm/authentik/` (`pg_restore`).
- The forward-auth middleware takes one address and follows the first worker. During a homelab drain, after a move of Authentik to normandy, the routing mesh on homelab is down with it, so forward auth fails until the generator points at normandy. Pointing the middleware at `https://auth.ryzhkov.dev` (through Traefik's own load balancer) would survive a drain; that is a batch 0 file and a design choice for the lead.
